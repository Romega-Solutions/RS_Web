# Romega Solutions - Design System Rules

This document provides a comprehensive analysis of the project's design system, intended to guide the implementation of Figma designs into the codebase using the Model Context Protocol.

## 1. Token Definitions

**Location:** `romega-next/app/globals.css`
**Format:** CSS custom properties within `@layer theme`.

The project uses two sets of tokens:
- **Romega Brand System:** Uses the `--rs-` prefix with HSLA values for granular control. Palettes include `primary`, `accent`, `neutral`, and `neutral-grey`.
  ```css
  --rs-primary-500: hsla(209, 100%, 45%, 1);
  --rs-accent-500: hsla(42, 94%, 45%, 1);
  --rs-neutral-100: hsla(209, 69%, 90%, 1);
  ```
- **Shadcn/Radix-compatible Tokens:** Uses HSL values without the `hsl()` wrapper, managed dynamically for light and dark modes via `prefers-color-scheme`.
  ```css
  --background: 0 0% 100%; /* Light */
  --primary: 221.2 83.2% 53.3%;
  ```

## 2. Component Library

**Location:** `romega-next/components/`
**Architecture:** The project strictly follows Atomic Design Principles.
- **Atoms:** Foundational UI elements (e.g., `atoms/Button/`, `atoms/AvatarPlaceholder/`).
- **Layout:** Structural components (e.g., `layout/CopyProtection.tsx`, `layout/Footer.tsx`).
- **Organisms:** Complex sections that piece together multiple atoms/molecules (e.g., `organisms/home/`, `organisms/careers/`).

**Base Primitives:** Integrates heavily with Radix UI (`@radix-ui/react-dialog`, `@radix-ui/react-tabs`, etc.) for accessible, unstyled primitives.

## 3. Frameworks & Libraries

- **UI Framework:** Next.js 16 (React 19) utilizing the App Router.
- **Styling:** Tailwind CSS v4 (configured via PostCSS) and standard CSS for custom rules.
- **Animations:** Framer Motion (`framer-motion`) and custom CSS keyframes.
- **Forms & Validation:** `react-hook-form` and `zod`.
- **Utilities:** `clsx` and `tailwind-merge` for conditional and merged class names (typically implemented via a `cn()` utility function).

## 4. Asset Management

**Location:** `romega-next/public/` and `romega-next/public/images/`
**Implementation:**
- Images should be loaded using Next.js `next/image` component for automatic optimization, resizing, and WebP/AVIF formatting.
- Assets are referenced with absolute paths starting from the root (e.g., `/images/bg-romega-logo.png`).

## 5. Icon System

- **Primary Icons:** `lucide-react` is the standard library for UI icons.
- **Custom Icons:** SVG icons are stored in `romega-next/public/images/`.
- **Convention:** Local icons follow an `icon-[name].svg` naming convention (e.g., `icon-accordion-arrow-down.svg`).

## 6. Styling Approach

The project uses a hybrid styling approach depending on component complexity:

- **Primary Approach:** TailwindCSS utility classes. Most elements should be styled using Tailwind defaults and custom theme extensions.
- **BEM Methodology:** For highly complex or reusable components (like `Button`), BEM methodology is used in conjunction with CSS Modules (e.g., `Button.module.css`).
  ```css
  /* Example BEM from Button.module.css */
  .button {}
  .button--primary {}
  .button__icon {}
  ```
- **Global Styles:** Broad typography rules and presets (e.g., `.text-merriweather-h1`, `.text-preset-hero`) are defined in `romega-next/app/styles/styles.css`.

## 7. Project Structure

- **`romega-next/app/`**: Next.js App Router for routing and page structure.
- **`romega-next/components/`**: React components following Atomic Design.
- **`romega-next/lib/`**: Contains utility functions (`utils.ts` for `cn`), Prisma configuration, Supabase clients, and security implementations.
- **`romega-next/docs/`**: Comprehensive documentation for implementation patterns (BEM, Atomic Design, etc.).
